3. RESUMO DA ARQUITETURA
------------------------
Solução completa de IaC + CI/CD DevSecOps + GitOps para os 5 microsserviços
do ToggleMaster (auth, flag, targeting, evaluation, analytics) rodando em Go.

Componentes provisionados via Terraform:
  - VPC com subnets públicas e privadas em 2 AZs (us-east-1a, us-east-1b)
  - Internet Gateway + NAT Gateway + Route Tables
  - EKS Cluster (Kubernetes 1.29) com Node Group t3.medium
    * Usa a LabRole existente (AWS Academy — sem criação de IAM roles)
  - 3 instâncias RDS PostgreSQL 15.5 (auth-db, flag-db, analytics-db)
  - 1 Cluster ElastiCache Redis 7.0
  - 1 Tabela DynamoDB (ToggleMasterAnalytics) com PAY_PER_REQUEST
  - 1 Fila SQS + Dead-Letter Queue
  - 5 repositórios ECR (togglemaster/{auth,flag,targeting,evaluation,analytics})
  - Backend remoto S3 com versionamento e use_lockfile=true

Pipeline CI/CD (GitHub Actions) por microsserviço:
  Stage 1 — Build & Unit Test: go build + go test -race
  Stage 2 — Lint: golangci-lint (errcheck, gosec, staticcheck, gofmt, etc.)
  Stage 3 — Security Scan:
    * SAST: gosec (vulnerabilidades no código-fonte)
    * SCA:  Trivy fs scan (vulnerabilidades nas dependências)
    * Regra de bloqueio: saída com exit code 1 em vulnerabilidade CRÍTICA
  Stage 4 — Docker Build & Push:
    * Build da imagem multi-stage (distroless/nonroot)
    * Container scan com Trivy (CRITICAL = falha)
    * Push para ECR com tag v1.0.0-<commit-hash>
  Stage 5 — Update GitOps:
    * Atualiza a tag da imagem em gitops/apps/<service>/deployment.yaml
    * Commit automático no repositório via github-actions[bot]

GitOps com ArgoCD:
  - ArgoCD instalado no namespace argocd do cluster EKS
  - AppProject "togglemaster" com escopo limitado ao namespace togglemaster
  - 5 Applications ArgoCD (uma por serviço) com:
    * automated sync (prune + selfHeal)
    * targetRevision: main
    * retry com backoff exponencial

4. DESAFIOS E DECISÕES
----------------------
a) AWS Academy sem criação de IAM:
   Solução: data source `aws_iam_role.lab_role` para referenciar a LabRole
   existente tanto para o control-plane do EKS quanto para os Node Groups.

b) Estado Terraform remoto sem custo extra:
   Usamos um bucket S3 simples (versionado + criptografado) com use_lockfile=true
   (recurso nativo do Terraform >= 1.10), dispensando tabela DynamoDB para lock.

c) Microsserviços sem dependências externas:
   Todos os 5 serviços foram escritos usando apenas a stdlib do Go, zerando o
   risco de SCA falso-positivo na entrega inicial.

d) Pipeline reutilizável:
   Um único _ci-template.yml (workflow_call) é referenciado pelos 5 workflows
   de microsserviços, evitando duplicação e facilitando manutenção.

e) Demonstração de bloqueio de segurança:
   Workflow demo-security-block.yml dedicado para a cena do vídeo onde o
   pipeline falha. Basta adicionar uma dependência vulnerável conhecida no
   go.mod do serviço auth e fazer push em uma branch demo/*.
